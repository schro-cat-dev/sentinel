# 防御境界マップ・ギャップ分析

## 概要

SDK → gRPC → Go Server の全パイプラインにおける防御境界を図示し、各境界でのセキュリティチェックの有無を分析する。

## 多層防御の評価

### 入力バリデーション — 3重防御

1. SDK `log-validator.ts` — ランタイム型・サイズ・ホワイトリスト検証
2. protobuf — スキーマベース型安全デシリアライズ
3. Go `sanitizer.go` — フィールド長・UTF-8・null byte・ホワイトリスト検証

**評価**: 非常に強固。SDKとGoサーバの制限値が一致しており、整合性が保たれている。

### PII保護 — 2重マスキング

1. SDK `masking-service.ts` — 8種PII + REGEX + KEY_MATCH
2. Go `masking.go` — 4種PII + ポリシーベース

**評価**: 良好。`dual` モードでは2重マスキングとなり、PII漏洩リスクが最小化される。

### 暗号化完全性 — SDK/Go独立

1. SDK — SHA-256 キーなしハッシュ（ローカル整合性）
2. Go — HMAC-SHA256 キー付きハッシュ（改竄検知）

**評価**: 意図的な設計差。remoteモードではGoサーバのHMACが有効。

### 認証 — 2層

1. gRPC interceptor — API Key検証
2. middleware/auth — TokenValidator (Static/Cached/Noop)

**評価**: 2つの認証層が存在するが、interceptorの定数時間比較の欠如が弱点。
