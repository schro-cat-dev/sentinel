## テスト設計原則

1. **TDD**: 機能実装前にテストを書き、Red→Green→Refactorサイクルを回す
2. **正常系・異常系・エッジケース**: 各機能に対して最低3パターン
3. **設定反映検証**: configの各フィールドがパイプライン動作に反映されることをE2Eで検証
4. **攻撃者視点**: セキュリティテストはCWE番号と攻撃シナリオを明記
5. **リグレッション防止**: 修正した脆弱性には必ず再現テストを付与
6. **網羅性**: バリデーション・マスキング・検知・タスク生成の全分岐を検証
